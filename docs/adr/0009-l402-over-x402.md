# ADR-0009: L402 (Lightning) is the paid-HTTP primitive, not x402

**Date:** 2026-10-07 · **Status:** accepted · Implemented in `packages/rails/src/compute/l402.ts`

## Context
Two "HTTP 402" protocols are in use for agent payments. **L402** (Lightning Labs; formerly LSAT)
returns a macaroon and a BOLT11 invoice; the client pays over Lightning and retries with
`Authorization: L402 <macaroon>:<preimage>`. **x402** (Coinbase) settles in USDC on Base with a
signed payment header.

## Decision
- The compute rail speaks **L402/LSAT only**. This is a bitcoin product: the user's wallet is a
  Lightning wallet, the budget is in sats, and L402 settles with the same wallet socket (ADR-0006)
  every other rail uses. x402 would require a second asset, a second key, and a custody story.
- The adapter **never pays**. It parses the challenge, decodes the invoice, and hands the amount
  to the executor, which compares it with the approved ceiling *before* the wallet is touched.
  A challenge above the ceiling fails with `AMOUNT_OUT_OF_RANGE` and nothing moves.
- Paid credentials are cached **per host** with a TTL, so polling or a follow-up request reuses
  the macaroon:preimage instead of paying again. A cached credential the server rejects yields a
  fresh challenge, not an error.
- Redirects are never followed with a credential attached. Bodies are read up to a bound
  (1 MB default) and truncated with a marker; streaming bodies are a later concern.
- `PayL402` carries `method`, `body` and `headers` so POST endpoints (LLM chat completions) work.
  The rail owns the `Authorization` header; callers cannot set it.
- `@getalby/lightning-tools` provides the header parser and invoice decoder; its own
  `fetchWithL402` helper is not used because it pays inside the helper, bypassing policy.

## Consequences
- Any Lightning-gated API (llm402.ai, LightningProx, Aperture-fronted services) is reachable with
  `fetch_l402` and a sats ceiling. x402-only endpoints are not, by design.
- The agent sees response bodies wrapped as untrusted text (ADR-0008).
